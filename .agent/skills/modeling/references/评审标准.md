# 独立评审标准（L2）

独立评审者（reviewer）是对抗性、只读的质检角色。每位 reviewer 拿到同样的原始证据与同一份本文件，但彼此隔离、互不知晓对方结论。

## 独立性要求

- 每位 reviewer 是全新上下文、未参与三件套编写或修订的只读实例。
- 只读，不修改任何权威产物；发现问题只输出 findings，由作者返工。
- 评审模型隔离：按 `tools_config.yaml` 的 `review` 段指定 reviewer 模型；隔离机制待定，见该段 TODO。

## 评审输入（只读）

- `competition/problem/`、`competition/data/`、`competition/rules/`
- 三件套：`题目分析报告.md`、`术语表格.md`、`model-contract.json`
- `EXT_REF/model-contract.schema.json`（核对结构）

**不提供**：作者的预期结论、作者自检结果、上一版评审结果、任何「请确认正确」的诱导。

## 评审维度

1. **最小充分性**：模型集合是否最小且充分，每个模型的角色（primary/comparison/validation/serial_stage）与必要性是否成立。
2. **公式正确性**：目标函数、约束、方程推导是否正确、量纲是否一致。
3. **约束覆盖**：是否遗漏题目关键约束或数据特征。
4. **可证伪验证**：验证方案能否被证伪，阈值是否有依据，失败条件是否明确。
5. **可实现性**：算法是否能用 Python 可靠实现，停止条件与复杂度是否说明。
6. **可追溯性**：参数/假设/来源是否有依据；文献是否可追溯到 DOI 或原始出版页面。
7. **创新映射**：创新点是否能映射到具体实现与验证，而非简单改名。

## 定级

| 级别 | 定义（示例） | 后果 |
|---|---|---|
| **P0 阻断** | 公式错误、约束遗漏致模型无法表达题目、验证不可证伪、ID/交叉引用断裂、文献无来源 | 必打回 |
| **P1 重要** | 参数缺单位、假设无依据、创新点无法映射实现、模型角色/必要性论证缺失 | 必打回 |
| **P2 建议** | 命名、措辞、图表建议 | 记录，不阻断 |

## 输出

每位 reviewer 输出一份 JSON，符合 `schemas/review-findings.schema.json`：

```json
{
  "reviewer_id": "R1",
  "model": "<评审模型>",
  "reviewed_at_utc": "2026-08-14T00:00:00Z",
  "independence_attested": true,
  "findings": [
    { "id": "F1", "severity": "P0", "claim": "...", "evidence": "...", "suggestion": "..." }
  ]
}
```

`independence_attested` 是评审者的可审计声明，不构成密码学身份证明。作者自检、脚本校验不得表述为独立评审通过。
