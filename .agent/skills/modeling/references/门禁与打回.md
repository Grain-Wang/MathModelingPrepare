# 门禁与打回

建模阶段只有一个门禁 `M1`，但它由四级检查组成，任一不通过即打回重改。

## 四级检查

```
L0 确定性 Schema 校验 —— 脚本，无模型参与
    validate_model_contract.py，exit 0 才通过
        │
        ▼
L1 作者自检 —— 按 references/质检清单.md 逐条确定性勾选
        │
        ▼
L2 双独立评审 —— run_review.py 调外部模型（R1/R2），按 references/评审标准.md
        │
        ▼
L3 门禁裁定 —— generate_gate_receipt.py 汇总 L0–L2 写入 qa/M1.json，validate_gate_receipt.py 校验
        │
   ┌────┴────┐
   │ PASS    │ FAIL / BLOCKED
   ▼         ▼
进入编码   打回重改（带回返工建议）
```

## 双 reviewer 共识规则

- 派发两个未参与编写的只读 reviewer，各产出 findings。执行命令：

  ```text
  python .agent/skills/modeling/scripts/run_review.py
  ```

  产出 `qa/R1.json`、`qa/R2.json`（外部模型异源评审，见 `tools_config.yaml` 的 `review.reviewers`）。
- **阻断阈值：P0 与 P1 均阻断**（默认，严格）。
- 交叉合并：同一问题 R1/R2 结论冲突时，**取更严重定级**，并记录分歧。
- `consensus = pass` 当且仅当两位 reviewer 的 findings 均无未解决 P0/P1；否则 `fail`。

## 回执 `qa/M1.json`

生成命令（汇总 L0–L2 → 裁定 status → 写入 `projects/02_modeling/qa/M1.json`）：

```text
python .agent/skills/modeling/scripts/generate_gate_receipt.py --check
```

`--check` 会在生成后自动跑 validate_gate_receipt.py 自校验。结构见 `schemas/gate-receipt.schema.json`，必含：

- `gate`、`status`（PASS/FAIL/BLOCKED）
- `inputs`：输入快照（role + 相对路径 + sha256 + 字节数），至少含三件套的 `model_contract`、`analysis_report`、`terminology_table`；`problem_statement` 在提供 `--problem` 时加入
- `checks`：L0/L1/L2/L3 各级结果与退出码
- `independent_review`：两位 reviewer 的 `reviewer_id`/`model`/`independence_attested`/`findings` + `consensus`
- `findings`：合并后的全部发现（含 severity，id 加 `R1.`/`R2.` 前缀）
- `rework_suggestions`：返工建议

独立校验命令：

```text
python .agent/skills/modeling/scripts/validate_gate_receipt.py --receipt projects/02_modeling/qa/M1.json
```

`validate_gate_receipt.py` 校验：回执符合 schema、每个输入 sha256 与磁盘一致、status 语义自洽（PASS 必须无 P0/P1 且双 reviewer 齐备）。exit 0 才认为回执可信。

## 打回重改循环

```
draft → L0(exit≠0→draft) → L1(未过→draft) → L2(有P0/P1→draft) → M1
         ↑__________________________________ FAIL/BLOCKED 带返工建议 ←┘
```

- 每次打回必须**修订三件套**（不新建平行版本），在回执中记录返工项。
- 三件套发生实质变化后，原 `qa/M1.json` 回执立即失效，必须重新生成输入快照并全量重跑 L0–L3。
- 缺输入/缺权限/缺证据判 `BLOCKED`；有错需返工判 `FAIL`。
