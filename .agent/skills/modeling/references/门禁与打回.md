# 校验、评审与打回

建模阶段采用“确定性校验 + 作者自检 + 两个独立评审渠道”，不设置自动门禁或生成门禁回执。

## 执行顺序

```text
三件套草稿
    │
    ▼
确定性 Schema 校验 —— validate_model_contract.py，exit 0 才通过
    │
    ▼
作者自检 —— 按 references/质检清单.md 逐条核对
    │
    ├── DeepSeek API —— run_review.py，输出 qa/R1.json
    │
    └── ChatGPT Pro 网页端 —— 只读指定仓库内容，直接给参赛队员反馈
            │
            ▼
参赛队员汇总并确认反馈
    ┌───────┴────────┐
    │ P0/P1 已处理   │ 仍有 P0/P1
    ▼                ▼
进入编码          打回修订三件套
```

## 两个评审渠道

### DeepSeek API

执行：

```text
python .agent/skills/modeling/scripts/run_review.py
```

脚本只调用 `tools_config.yaml` 中 `access: api`、`provider: deepseek` 的 reviewer，读取 `AGENTS.md`、文献唯一真相源、三件套和只读题目材料（默认 `competition/`，可用 `--problem` 调整），输出 `projects/02_modeling/qa/R1.json`。

### ChatGPT Pro 网页端

- 由参赛队员在网页端发起，不通过 `run_review.py`，不配置或读取 OpenAI API Key。
- 仓库权限为只读，读取范围以 `tools_config.yaml` 的 `repository_read_scope` 为准。
- 使用 `references/评审标准.md` 的相同维度和 P0/P1/P2 分级给出反馈。
- 不读取 DeepSeek 的反馈，避免两个渠道相互影响。
- 网页端不写仓库；参赛队员负责保存、核实和转交反馈。

## 处理规则

- **P0 阻断、P1 重要**：均须由参赛队员确认并处理；处理完成前不进入编码阶段。
- **P2 建议**：记录后由参赛队员决定是否采用。
- 两方对同一问题定级冲突时，参赛队员先按更严重级别检查，不自动裁定。
- 任何评审结论都不是最终学术裁定；参赛队员承担最终责任。

## 打回重改循环

```text
draft → Schema 校验 → 作者自检 → 两方独立评审 → 队员确认
   ↑_____________________________________ P0/P1 未解决 ┘
```

- 每次打回直接修订三件套，不新建平行版本，并在报告中说明变更。
- 三件套发生实质变化后，原有评审只代表旧版本；应重新运行 DeepSeek API 评审并让 ChatGPT Pro 网页端复核。
- 缺少题目、数据、来源或权限时标注为待确认项，不由模型补造事实。
