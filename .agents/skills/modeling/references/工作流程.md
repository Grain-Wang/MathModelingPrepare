# 建模工作流程

## 一、读题与附件

1. 枚举题目、附件、数据表、图片与模板，记录文件哈希或明确版本。
2. 按子问题列出目标、约束、输入、输出与评价口径。
3. 检查数据字段、单位、缺失、异常、重复、时间顺序与空间关系。
4. 无法确认的事实写成待确认项，不自行补造。

## 二、理解后形成结论目标

先回答「题目最终要说明什么」，再讨论模型。结论目标应描述输出类型与评价标准，不预写数值结果。

示例：

- 输出满足全部容量与时间窗约束的配送方案，并比较成本与稳定性。
- 输出未来各期预测及其不确定性，并用留出数据检验误差。

## 三、选择模型

每个子问题采用**最小充分模型集合**。为每个模型指定 `primary`、`comparison`、`validation` 或 `serial_stage` 角色；只有不同机制、必要串联接口或能改变可信度判断的独立验证才增加模型。物理问题按「模型族」组织（同一物理机制、同一核心变量的不同近似精度视为一个模型族）。

选择理论详见 `EXT_REF/建模设计理论.md`，常见组合模式详见 `EXT_REF/常见模式.md`。

## 四、搜索理论依据

需要文献时，从 `reference/literature/zotero_library.bib` 解析可用文献；AI 发现的文献必须先导入 Zotero 才能引用。引用必须能追溯到 DOI 或原始出版页面。

## 五、写交付物（三件套，落点 `projects/02_modeling/`）

### `题目分析报告.md`

至少包括：

1. 题目与附件清单
2. 子问题拆解
3. 数据理解与预处理计划
4. 假设及依据
5. 每题模型与数学定义
6. 算法步骤、输入输出与验证方式
7. 编程依赖与候选图表
8. 逐子问题证据计划：核心主张、所需公式/结果/图/表/代码/文献/诊断及图表类别，允许明确「不需要图」
9. 风险与回退条件
10. 文献依据

### `术语表格.md`

至少包括中文术语、英文术语、符号、定义、单位、首次出现位置和禁止混用的近义词。

### `model-contract.json`

按照 `EXT_REF/model-contract.schema.json` 输出稳定的机器可读合同，完整记录项目 ID、竞赛、题目、子问题、输入输出、模型角色、公式、参数、约束、算法、验证、风险、符号、假设和来源。不得用空对象或自由字段绕过合同。

## 六、校验与双通道评审

见 `references/门禁与打回.md`。顺序：确定性 Schema 校验 → 作者自检 → DeepSeek API 评审与 ChatGPT Pro 网页端评审。网页端只读指定仓库内容，不使用 API Key；两方 P0/P1 经参赛队员确认处理完毕后，才进入编码阶段。

## 七、反馈修正

收到评审反馈或计算阶段返回实现证据后，直接修订三件套并说明变更，重新完成校验、自检和两方复核；不创建同义版本文件。
