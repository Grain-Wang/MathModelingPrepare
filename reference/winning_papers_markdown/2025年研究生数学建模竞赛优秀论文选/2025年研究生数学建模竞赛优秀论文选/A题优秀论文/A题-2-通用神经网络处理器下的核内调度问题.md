# **中国研究生创新实践系列大赛 “华为杯”第二十二届中国研究生 数学建模竞赛** 

## 题 目: 通用神经网络处理器下的核内调度问题 

## ~~摘 要：~~ 

边缘计算时代，通用神经网络加速处理器（NPU）的性能瓶颈日益凸显，尤其是在适 配复杂神经网络算子时的软件调度效率。本研究聚焦 <u>SIMD 架构 NPU 的核内调度难题，旨</u> 在突破传统人工编排的局限性，提出一套通用、高效、自适应的细粒度计算图优化调度框 架。 

首先，针对算子计算图规模庞大且异构的特性，设计了一套 基于领域搜索的贪心算法 ， 通过结合 优先级策略 与 禁忌搜索机制 ，高效生成满足拓扑序的节点执行序列。该算法以最 小 ~~化执行过程中的缓存驻留峰值为首要目标，通过智能调整内存管理节点（ALLOC/~~ FREE） 的相对位置，实现内存使用的 亚线性增长 ，该算法相对于节点总数 N 的时间复杂度为 _O_ ( _N_<sup>2</sup> )，为后续优化奠定坚实基础。 

其次，在严格的硬件缓存容量限制下，引入 自适应二进制量子粒子群优化（ **ABQPSO** ） 算法 ，融合 量子动力学 与 多维混合编码策略 。该算法能够动态决策 SPILL 操作的介入时机 与缓存物理地址的精细分配，通过 分层修复与局部搜索机制 ，最大限度地降低总额外数据 搬运量，有效应对缓存碎片化与资源冲突挑战，展现了在资源约束下优秀的自适应能力。 

最后，在总额外数据搬运量指标不显著增加的约束前提下，针对算子优化中“执行时 间缩短”与“数据搬运量控制”相互制约的多目标优化困境，设计了一种 基于双种群多目 标进化算法 的优化框架。该框架通过维护 收敛种群 与 探索种群 双种群结构，结合 协同遗传 操作与 差异化环境选择机制 ，有效挖掘算子并行计算空间以降低总运行时间。为验证框架 有效性，在 Matmul、FlashAttention、Conv 等典型算子的大规模计算图上开展实验，结果 表明：该优化框架可实现 10%—30% 的性能指标综合提升，充分证明了其在多目标算子优 化场景中的实用性与优越性。 

本研究构建的层次化、多目标协同优化模型与算法体系，优化了 NPU 核内调度问题， 为突破 AI 模型在边缘设备上的端到端推理性能与能效提供了一种新视角。 关键词： 通用神经网络处理器；核内调度；多目标优化；量子粒子群优化

### 一、问题重述 

#### **1.1** 问题背景 

随着人工智能技术的快速发展，神经网络模型在边缘计算设备上的部署需求日益增 长。通用神经网络加速处理器（NPU）因其高效的并行计算能力成为边缘推理任务的首选 硬件平台。其中，基于单指令多数据流（SIMD）架构的处理器设计简单、面效高，但其软 件模型适配的复杂性成为大规模商用的关键瓶颈。 

在神经网络推理过程中，算子（如矩阵乘 Matmul、卷积 Conv、注意力 Attention 等） 是最小任务单元，其执行效率直接影响模型在平台上的端到端推理性能。SIMD 架构硬件 平台上的计算过程可拆解为由硬件单元操作构成的细粒度计算图，并通过手工或自动方式 编排成可执行的任务。然而，这类计算图具有高度异构性：算子类型多样、输入形状动态 变化、拓扑结构复杂，导致人工编排方式难度大、缺乏通用性且效率低下，无法适应日益 复杂的计算场景。 

因此，设计一种通用调度算法，自动将计算图中各算子操作编排调度到各硬件单元上 执行，成为当前研究的迫切需求。该算法需要面向 SIMD 平台的硬件限制，给出由硬件单 元操作组成的计算图的优化调度顺序，使得多个不同单元能并行执行，缩短流水线延迟。 同时，调度算法还需考虑内存与计算协同，动态管理多级缓存，自动决定缓存数据换入换 出，减少数据搬运开销。 

计算图为有向无环图（DAG），节点分为两类：在特定硬件单元上执行的操作节点（如 COPY_IN、ADD、MU 等）和用于缓存资源分配的缓存管理节点（ALLOC/FREE）。调度 算法需要生成满足拓扑序的节点执行序列，并为所有缓存管理节点中的申请节点分配相应 类型的地址。硬件缓存资源有限，调度过程中需要考虑内存与计算协同，动态管理多级缓 存，减少数据搬运开销。 

#### **1.2** 问题提出 

本问题围绕通用神经网络处理器下的核内调度问题展开，具体分为三个具有层次关系 的子问题，每个子问题都有其独特的研究重点和技术挑战。 

第一个子问题要求设计调度算法生成计算图的节点执行序列，使得执行过程中所需驻 留的最大缓存容量尽可能小。该问题仅关注调度顺序，不涉及缓存分配策略。需要分析算 法的时间复杂度，并在给定的六个示例计算图上给出最大缓存驻留结果及调度序列。该问 题的技术难点在于如何通过调度序列的优化来压缩缓冲区的生命周期，减少缓存峰值使用 量。算法需要高效处理大规模计算图，节点数量可能达到数万级别，因此时间复杂度成为 重要的考量因素。最优调度序列的寻找需要考虑计算图的拓扑结构特征，以及不同类型节 点之间的依赖关系。 

在第一个问题得到的调度序列基础上，第二个子问题需要为计算图中各缓冲区分配物

理地址偏移，并在严格的硬件缓存容量限制下最小化总额外数据搬运量。当缓存空间不足 时，需要引入缓存换入换出操作（SPILL 操作），将部分数据临时移出至核外内存（DDR）， 并在需要时重新载入。该问题的核心挑战在于如何在有限的缓存空间内实现最优的资源分 配，同时最小化因 SPILL 操作带来的额外数据搬运开销。需要从减少缓存碎片的角度优化 分配方案，考虑不同缓冲区的生命周期重叠情况，以及硬件缓存的空间约束。总额外数据 搬运量的计算需要区分缓冲区是否被 COPY_IN 节点使用，这两种情况下的计算方式存在 显著差异。 

第三个子问题是在前两个问题的基础上，进一步优化总运行时间，同时保证总额外数 据搬运量不显著增加。性能优化策略可以从调度顺序和缓存分配方案两个维度入手，通过 调整节点执行顺序实现各硬件单元的流水并行，或者通过地址复用策略减少缓存碎片。该 问题要求实现多项性能指标的联合优化，需要在执行时间和数据搬运量之间寻找最佳平衡 点。优化策略需要考虑不同硬件单元的特性，充分利用 Cube 核、Vector 核以及各种数据搬 运单元（MTE1/2/3 和 FIXP）的并行处理能力。同时还需要考虑不同计算图结构特征对优 化效果的影响。 

三个子问题呈现出明显的层次递进关系：问题 1 是基础，通过最小化缓存驻留为后续 问题提供优化空间；问题 2 在硬件限制下引入缓存管理机制，着重减少数据搬运开销；问 题 3 进行综合优化，实现性能与能效的最佳平衡。 

整体面临的挑战主要体现在三个方面：首先是计算图规模大且结构异构，示例计算图 节点数达数万，且包含 Matmul、FlashAttention、Conv 等多种结构类型，需要设计具有高 度通用性的算法。其次是硬件约束复杂，多级缓存容量有限，需要充分考虑不同执行单元 的并行特性。最后是多目标优化难题，需要同时考虑缓存驻留、数据搬运量和执行时间等 多个指标，这些指标之间可能存在相互制约的关系。解决问题的技术途径需要结合图论优 化、资源调度算法、内存管理策略等多个领域的知识，形成系统性的解决方案。算法设计 需要兼顾理论最优性和实际可操作性，能够在合理的时间内处理大规模计算图调度问题。 

### 二、模型假设 

1. 计算图节点属性信息完整准确，无缺失或错误； 

2. 依赖边完整反映数据流和控制流约束，无冗余或缺失； 

3. 缓冲区引用一致，所有标识符均有对应管理节点； 

4. 执行单元性能稳定，周期数固定可预测； 

5. 缓存访问延迟均匀，无局部性性能差异； 

6. 算法执行资源充足，不受计算资源限制； 

7. 对于任意计算图都存在可行调度方案； 

8. 硬件运行无故障，执行单元正常工作；

- ( **2** ) 优化目标的序列敏感性 ：目标函数 max( _V_ stay) 的值完全依赖于节点执行的先后顺序。其 本质是通过协调 ALLOC 与 FREE 节点的相对位置，使数据缓冲区的生命周期尽可能避 免重叠，从而降低内存使用的峰值。微小的序列调整可能导致峰值显著变化，目标函 数呈现较强的非线性。 

- ( **3** ) 问题规模的挑战性 ：根据附录 E 提供的示例，计算图节点规模巨大（从上千至数万节 点）。这要求算法设计必须具有较低的时间复杂度，任何超过 _O_ ( _n_<sup>2</sup> ) 的复杂算法都可能 面临计算效率瓶颈。

#### **6.1** 问题三分析 

问题三的核心挑战在于如何在总额外数据搬运量不显著增加的前提下，有效降低算子 的总运行时间，这是一个典型的多目标优化问题。与前两问单一目标的优化模式不同，本 

28 

问题需要同时权衡数据移动效率与计算资源利用率之间的复杂关系，这种双重目标的追求 使得优化过程更加复杂且具有挑战性。 

SIMD 架构的硬件特性深刻影响了这一问题的求解路径。该架构包含多个异构执行单 元，这些单元既具有资源独占性又具备单元间并行性，形成了独特的计算环境。前两问的 优化策略虽然有效降低了缓存峰值和数据搬运量，但这种优化往往是通过串行化调度来实 现的，在提升数据效率的同时却牺牲了硬件固有的并行计算能力，最终导致总执行时间偏 长。相反地，如果过度追求并行度，又会加剧缓存资源竞争，触发更多 SPILL 操作，反而 增加额外数据搬运量。这种内在的权衡关系构成了问题三需要解决的核心矛盾，需要在两 个相互竞争的目标之间找到精妙的平衡点。 

从数学本质来看，问题三可以表述为一个双目标优化问题，需要同时最小化总额外数 据搬运量和总执行时间，同时满足所有硬件与拓扑约束。这两个目标之间存在天然的冲突 关系，形成了帕累托最优前沿。这意味着不存在单一的最优解，而是存在一组非支配解， 每个解都在不同程度上实现了两个目标的平衡，为决策者提供了多种选择空间。 

针对这一复杂问题，我们提出基于多层次协同优化的解决思路。在调度层面采用关键 路径识别技术，优先调度长周期计算节点，提高计算密集型操作的优先级，同时将数据搬 运操作与计算操作重叠执行以隐藏延迟。在资源分配层面实施生命周期敏感的缓存管理策 略，通过精细调整 ALLOC 和 FREE 节点的位置，压缩缓冲区的无效驻留时间，在不增加 缓存峰值的前提下为其他操作腾出空间。在 SPILL 策略层面设计面向并行的操作调度，将 SPILL 操作与空闲硬件单元相匹配，避免在计算密集型阶段执行数据搬运，从而最大化硬 件利用效率。具体处理思路如图6.13所示。

#### **6.2.3** 模型求解 

在多目标进化算法中，初始种群的多样性直接影响优化过程的质量与收敛速度。如果 初始解分布过于集中，算法可能会陷入局部最优，但若初始解过于分散，则算法难以探索 完整的解空间。为避免因初始样本分布不均导致算法准确性低，本文采用拉丁超立方抽样 生成初始种群，该方法能在高维决策空间中保持样本均匀性。其基本思想是在每一个变量 的定义域上，将取值区间均匀划分为若干个子区间，随后在每个子区间内随机选择一个点， 最后将各个维度的样本点组合起来，形成初始解。这样既保证了每个维度上取值的均匀性， 又保留了一定的随机性，从而增强了解的多样性。 

双种群多目标进化算法 (DPEA) 是一种基于多目标进化思想的优化算法，其核心特征 是通过维护两个具有不同进化导向的种群来平衡算法的收敛性与多样性 [5]。与传统单种 群进化算法不同，DPEA 同时维护两个相互独立又彼此协作的种群：一个收敛种群（P1） 专注于快速逼近帕累托前沿，另一个探索种群（P2）则致力于在解空间中进行广泛搜索， 防止算法陷入局部最优。这种双种群协同进化的机制，使得 DPEA 在处理复杂多目标优化 问题时表现出色。 

根据非支配排序和拥挤度计算，优先选择收敛性好的个体来更新 P1，根据约束满足 度，选择可行性较高的个体更新 P2 以增强探索能力，实时更新外部存档，保存历史最优 的帕累托解集。当迭代次数达到最大迭代次数时，停止进化并输出得到的帕累托最优解集。 子代生成采用协同进化策略，两个种群相互提供交配个体：

GenerateOffspring( _P_ 2 _, P_ 1) = CrossoverAndMutate( _P_ 2 _,_ TournamentSelect( _P_ 1)) (6.69)

针对问题一的最小缓存驻留调度目标，我们采用了基于领域搜索的贪心算法。该算法 展现出显著的优势：首先，其高效性与可扩展性极佳，通过贪心初始化结合禁忌搜索进行 迭代优化，能以多项式时间复杂度（贪心阶段为 _O_ ( _N_<sup>2</sup> )，领域搜索为 _O_ ( _K · M · N_ )）处 理节点数高达数万级别的大规模计算图，且严格遵循拓扑序和 L0 缓存单一驻留约束。其 次，通过智能调整内存管理节点（ALLOC/FREE）的优先级，算法显著压缩了缓冲区的生 命周期，实现了缓存驻留峰值的亚线性增长，尤其在 Conv_ Case1 等场景下表现卓越。此 外，算法能根据不同算子的结构特点自适应调整调度策略，取得良好的“抑峰”效果。然 而，该算法也存在局限性：作为启发式算法，其本质上无法保证找到全局最优解，存在陷 入局部最优的风险，且解的质量可能依赖于初始优先级函数的设计。当前的优先级函数权 重是经验性设置的，且邻域操作的完备性可能未能覆盖所有潜在的优化结构。针对上述局 限，未来的改进方向包括：探索使用强化学习或自适应机制动态调整优先级函数中的权重 系数；引入针对特定算子类型（如大规模 Matmul 中的分块操作）的定制化邻域操作，或

对于问题二的硬件缓存约束下最小化总额外数据搬运量目标，我们引入了自适应二进 制量子粒子群优化（ABQPSO）算法。该算法的显著优势在于其强大的全局搜索能力，融 合了量子计算的全局探索与粒子群优化的快速收敛特性，能有效应对高维、离散且复杂的 缓存分配与 SPILL 决策问题。创新的四段式混合编码策略能够同时优化序列、缓存分配、 SPILL 标志和 SPILL 偏移等多种异构决策变量，全面解决了问题二的复杂性。此外，算法 结合罚函数法与多阶段分层修复算子，确保了严格的约束满足性，并在 Conv_Case1 等极 端场景下展现出“更多次、小规模”SPILL 的精细化内存管理有效性。然而，ABQPSO 的 计算开销相对较大，其复杂的量子态更新、测量以及多阶段修复算子导致较高的计算成本 （时间复杂度为 _O_ ( _NKL_ + _NKL_<sup>2</sup> + _NKLM_ )）。同时，算法的性能仍对初始参数设置敏感， 且修复算子的效率也可能影响优化进程。针对这些挑战，未来的改进方向包括：探索将 ABQPSO 中的并行计算部分移植到 GPU 等异构计算平台以大幅缩短求解时间；优化或简 化修复算子，例如通过预测性检查避免无效修复尝试或设计更高效的局部修复策略；结合 ABQPSO 与更快速的局部搜索方法形成混合策略或超启发式框架；以及进一步优化 SPILL 操作的动态时机选择和地址重映射策略，使其在对性能影响最小的时段执行。
